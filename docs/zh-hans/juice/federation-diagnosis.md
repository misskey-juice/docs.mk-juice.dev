# 联合诊断

面向版主的功能,在与其他服务器的联合出现问题时,可以确认在哪里中断了。

## 使用方法

打开已联合服务器的信息页面(`/instance-info/<主机名>`)中的"诊断"标签页,点击"开始诊断"。结果出来可能需要几十秒。

诊断不会向对方服务器投递任何内容,只会查询信息。

## 检查的项目

### 本服务器的设置与状态

| 项目 | 内容 |
| --- | --- |
| 联合范围 | 本服务器是否设置为不联合,或设置为只与指定服务器联合而对方不在列表中 |
| 屏蔽 | 本服务器是否屏蔽了对方服务器 |
| 静音 | 本服务器是否静音・媒体静音了对方服务器 |
| 停止投递 | 是否停止了向对方的投递(手动・对方回应 410 Gone・长时间无响应・软件被列为对象等) |
| 对方的响应 | 向对方服务器的投递是否持续失败 |
| 最后一次收到对方内容的时间 | 是否收到过对方服务器的内容,是否已经有一段时间没有收到 |
| 等待重试的投递 | 是否有失败后等待重试的投递 |

### 对对方服务器的请求

| 项目 | 内容 |
| --- | --- |
| 域名解析(DNS) | 能否解析对方的域名(使用代理的设置下不检查) |
| HTTPS 连接 | 能否通过 HTTPS 连接对方服务器(也会检查证书过期・名称不匹配等) |
| NodeInfo(服务器信息) | 能否获取对方服务器的信息 |
| WebFinger(用户查询) | 能否在对方服务器上查询用户 |
| 带签名获取用户信息 | 能否带签名获取本服务器已知的对方用户信息。同时会显示[签名密钥](#签名密钥)的类型 |
| inbox(投递目标)的响应 | 对方服务器的 inbox 是否接受投递。用不带签名的空 POST 检查,因此对方会不处理内容直接拒绝,不会构成投递。404・405・410 视为"不接受投递"(有问题),429 为注意,5xx 为有问题,其他(401・403・400・2xx)为正常 |

### 签名密钥

"带签名获取用户信息"中也会显示签名所用密钥的类型。可以区分 RSA(密钥长度)・Ed25519・ECDSA。

- **本服务器的签名**: 本服务器签名所用的密钥和算法(RSA・rsa-sha256 及密钥长度)
- **对方公开的密钥**: 对方用户公开的密钥(`publicKey` 以及 `assertionMethod` 中的 Multikey)
- **本服务器保存的对方密钥**: 用于验证对方发来的签名的密钥。如果对方更换了密钥而保存的密钥仍是旧的,就无法验证签名

即使获取用户信息失败,也会显示本服务器的签名和保存的对方密钥。

## 结果的看法

每个项目会显示"正常""注意""有问题""未检查"之一,以及原因(HTTP 状态码或连接错误等)。从上往下依次查看,就能知道联合在哪里中断。

::: tip
由于很多服务器不验证签名就返回用户信息,即使对方屏蔽了本服务器,"带签名获取用户信息"也可能显示"正常"。另外,如果一段时间没有收到对方的任何内容,可能是对方停止了向本服务器的投递,或屏蔽了本服务器。
:::

## 面向开发者

API 为 `admin/federation/diagnose-instance`(面向版主。权限为 `write:admin:federation`)。每个项目都有 `keys`(签名密钥的类型),inbox 不接受投递时的结果为 `inboxNotFound`。
