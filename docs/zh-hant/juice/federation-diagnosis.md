# 聯邦診斷

給版主的功能,在與其他伺服器的聯邦出現問題時,可以確認在哪裡中斷了。

## 使用方法

開啟已聯邦伺服器的資訊頁面(`/instance-info/<主機名稱>`)中的「診斷」分頁,點擊「開始診斷」。結果出來可能需要幾十秒。

診斷不會向對方伺服器傳送任何內容,只會查詢資訊。

## 檢查的項目

### 本伺服器的設定與狀態

| 項目 | 內容 |
| --- | --- |
| 聯邦範圍 | 本伺服器是否設定為不聯邦,或設定為只與指定伺服器聯邦而對方不在清單中 |
| 封鎖 | 本伺服器是否封鎖了對方伺服器 |
| 靜音 | 本伺服器是否靜音・媒體靜音了對方伺服器 |
| 停止傳送 | 是否停止了向對方的傳送(手動・對方回應 410 Gone・長時間無回應・軟體被列為對象等) |
| 對方的回應 | 向對方伺服器的傳送是否持續失敗 |
| 最後一次收到對方內容的時間 | 是否收到過對方伺服器的內容,是否已經有一段時間沒有收到 |
| 等待重試的傳送 | 是否有失敗後等待重試的傳送 |

### 對對方伺服器的請求

| 項目 | 內容 |
| --- | --- |
| 網域解析(DNS) | 能否解析對方的網域名稱(使用代理的設定下不檢查) |
| HTTPS 連線 | 能否透過 HTTPS 連線對方伺服器(也會檢查憑證過期・名稱不符等) |
| NodeInfo(伺服器資訊) | 能否取得對方伺服器的資訊 |
| WebFinger(使用者查詢) | 能否在對方伺服器上查詢使用者 |
| 帶簽章取得使用者資訊 | 能否帶簽章取得本伺服器已知的對方使用者資訊。同時會顯示[簽章金鑰](#簽章金鑰)的類型 |
| inbox(傳送目標)的回應 | 對方伺服器的 inbox 是否接受傳送。用不帶簽章的空 POST 檢查,因此對方會不處理內容直接拒絕,不會構成傳送。404・405・410 視為「不接受傳送」(有問題),429 為注意,5xx 為有問題,其他(401・403・400・2xx)為正常 |

### 簽章金鑰

「帶簽章取得使用者資訊」中也會顯示簽章所用金鑰的類型。可以區分 RSA(金鑰長度)・Ed25519・ECDSA。

- **本伺服器的簽章**: 本伺服器簽章所用的金鑰和演算法(RSA・rsa-sha256 及金鑰長度)
- **對方公開的金鑰**: 對方使用者公開的金鑰(`publicKey` 以及 `assertionMethod` 中的 Multikey)
- **本伺服器儲存的對方金鑰**: 用於驗證對方傳來的簽章的金鑰。如果對方更換了金鑰而儲存的金鑰仍是舊的,就無法驗證簽章

即使取得使用者資訊失敗,也會顯示本伺服器的簽章和儲存的對方金鑰。

## 結果的看法

每個項目會顯示「正常」「注意」「有問題」「未檢查」之一,以及原因(HTTP 狀態碼或連線錯誤等)。從上往下依序查看,就能知道聯邦在哪裡中斷。

::: tip
由於很多伺服器不驗證簽章就回傳使用者資訊,即使對方封鎖了本伺服器,「帶簽章取得使用者資訊」也可能顯示「正常」。另外,如果一段時間沒有收到對方的任何內容,可能是對方停止了向本伺服器的傳送,或封鎖了本伺服器。
:::

## 給開發者

API 為 `admin/federation/diagnose-instance`(給版主。權限為 `write:admin:federation`)。每個項目都有 `keys`(簽章金鑰的類型),inbox 不接受傳送時的結果為 `inboxNotFound`。
