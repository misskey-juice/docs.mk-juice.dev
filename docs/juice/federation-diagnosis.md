# 連合の診断

ほかのサーバーとの連合がうまくいかないとき、どこで止まっているかを確かめられる、モデレーター向けの機能です。

## 使い方

連合しているサーバーの情報のページ(`/instance-info/<ホスト名>`)の「診断」タブを開き、「診断する」を押します。結果が出るまで、数十秒かかることがあります。

診断は、相手のサーバーには何も配送しません。情報を問い合わせるだけです。

## 調べる項目

### このサーバーの設定・状態

| 項目 | 内容 |
| --- | --- |
| 連合の範囲 | このサーバーが連合しない設定か、決めたサーバーとだけ連合する設定で相手が一覧に入っていないか |
| ブロック | このサーバーが相手のサーバーをブロックしていないか |
| サイレンス | このサーバーが相手のサーバーをサイレンス・メディアサイレンスしていないか |
| 配送の停止 | 相手への配送を止めていないか(手動・相手が410 Goneと応答した・長い間応答しなかった・ソフトウェアが対象 など) |
| 相手の応答 | 相手のサーバーへの配送が失敗し続けていないか |
| 相手から最後に届いた日時 | 相手のサーバーから何か届いているか、しばらく止まっていないか |
| 再送を待っている配送 | 失敗して再送を待っている配送が無いか |

### 相手のサーバーへの問い合わせ

| 項目 | 内容 |
| --- | --- |
| 名前解決(DNS) | 相手のドメインの名前を解決できるか(プロキシを使う設定のときは確かめません) |
| HTTPSでの接続 | 相手のサーバーにHTTPSで接続できるか(証明書の期限切れ・名前の不一致なども調べます) |
| NodeInfo(サーバーの情報) | 相手のサーバーの情報を取得できるか |
| WebFinger(ユーザーの検索) | 相手のサーバーでユーザーを検索できるか |
| 署名付きでのユーザー情報の取得 | このサーバーが知っている相手のユーザーの情報を、署名付きで取得できるか。あわせて[署名の鍵](#署名の鍵)の種類も出します |
| inbox(配送先)の応答 | 相手のサーバーのinboxが配送を受け付けているか。署名の無い空のPOSTで確かめるので、相手は中身を処理せずに断り、配送にはなりません。404・405・410は「配送を受け付けていない」として問題あり、429は注意、5xxは問題あり、それ以外(401・403・400・2xx)は問題なしになります |

### 署名の鍵

「署名付きでのユーザー情報の取得」には、署名に使う鍵の種類も表示されます。RSA(鍵の長さ)・Ed25519・ECDSAを見分けます。

- **このサーバーの署名**: このサーバーが署名に使う鍵とアルゴリズム(RSA・rsa-sha256と鍵の長さ)
- **相手が公開している鍵**: 相手のユーザーが公開している鍵(`publicKey`と、`assertionMethod`のMultikey)
- **このサーバーが保存している相手の鍵**: 相手から届いた署名を確かめるのに使う鍵です。相手が鍵を変えたのに、保存している鍵が古いままだと、署名を確かめられません

ユーザー情報の取得に失敗しても、このサーバーの署名と、保存している相手の鍵は表示されます。

## 結果の見方

項目ごとに「問題なし」「注意」「問題あり」「確かめていません」のどれかと、その理由(HTTPのステータスコードや接続のエラーなど)が表示されます。上から順に見ていくと、どこで連合が止まっているかが分かります。

::: tip
「署名付きでのユーザー情報の取得」は、署名を確かめずに返すサーバーも多いため、相手がこのサーバーをブロックしていても「問題なし」になることがあります。また、相手から「しばらく何も届いていない」場合は、相手側でこのサーバーへの配送が止まっているか、こちらをブロックしている可能性があります。
:::

## 開発者向け

APIは`admin/federation/diagnose-instance`です(モデレーター向け。権限は`write:admin:federation`)。各項目に`keys`(署名の鍵の種類)があり、inboxが配送を受け付けていないときの結果は`inboxNotFound`です。
