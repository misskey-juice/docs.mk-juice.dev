# 연합 진단

다른 서버와의 연합이 잘 되지 않을 때, 어디서 멈춰 있는지 확인할 수 있는 모더레이터용 기능입니다.

## 사용법

연합 중인 서버의 정보 페이지(`/instance-info/<호스트 이름>`)의 "진단" 탭을 열고 "진단하기"를 누릅니다. 결과가 나올 때까지 수십 초가 걸릴 수 있습니다.

진단은 상대 서버에 아무것도 배달하지 않습니다. 정보를 문의할 뿐입니다.

## 확인하는 항목

### 이 서버의 설정·상태

| 항목 | 내용 |
| --- | --- |
| 연합 범위 | 이 서버가 연합하지 않는 설정인지, 정해 둔 서버와만 연합하는 설정이고 상대가 목록에 없는지 |
| 차단 | 이 서버가 상대 서버를 차단하고 있지 않은지 |
| 사일런스 | 이 서버가 상대 서버를 사일런스・미디어 사일런스하고 있지 않은지 |
| 배달 정지 | 상대에게 배달을 멈추고 있지 않은지(수동・상대가 410 Gone으로 응답함・오랫동안 응답하지 않음・소프트웨어가 대상 등) |
| 상대 서버의 응답 | 상대 서버로의 배달이 계속 실패하고 있지 않은지 |
| 상대 서버에서 마지막으로 받은 시각 | 상대 서버에서 무언가 오고 있는지, 한동안 멈춰 있지 않은지 |
| 재전송을 기다리는 배달 | 실패해서 재전송을 기다리는 배달이 없는지 |

### 상대 서버에 대한 요청

| 항목 | 내용 |
| --- | --- |
| 이름 해석(DNS) | 상대 도메인의 이름을 해석할 수 있는지(프록시를 쓰는 설정일 때는 확인하지 않습니다) |
| HTTPS 연결 | 상대 서버에 HTTPS로 연결할 수 있는지(인증서 만료・이름 불일치 등도 확인합니다) |
| NodeInfo(서버 정보) | 상대 서버의 정보를 가져올 수 있는지 |
| WebFinger(사용자 검색) | 상대 서버에서 사용자를 검색할 수 있는지 |
| 서명된 사용자 정보 가져오기 | 이 서버가 알고 있는 상대 사용자의 정보를 서명을 붙여 가져올 수 있는지. [서명 키](#서명-키)의 종류도 함께 보여 줍니다 |
| inbox(배달 대상)의 응답 | 상대 서버의 inbox가 배달을 받고 있는지. 서명 없는 빈 POST로 확인하므로, 상대는 내용을 처리하지 않고 거절하며 배달이 되지 않습니다. 404・405・410은 "배달을 받지 않음"으로 문제 있음, 429는 주의, 5xx는 문제 있음, 그 밖(401・403・400・2xx)은 문제 없음이 됩니다 |

### 서명 키

"서명된 사용자 정보 가져오기"에는 서명에 쓰는 키의 종류도 표시됩니다. RSA(키 길이)・Ed25519・ECDSA를 구별합니다.

- **이 서버의 서명**: 이 서버가 서명에 쓰는 키와 알고리즘(RSA・rsa-sha256과 키 길이)
- **상대가 공개한 키**: 상대 사용자가 공개한 키(`publicKey`와 `assertionMethod`의 Multikey)
- **이 서버가 저장한 상대의 키**: 상대에게서 온 서명을 확인하는 데 쓰는 키입니다. 상대가 키를 바꿨는데 저장된 키가 오래된 그대로면 서명을 확인할 수 없습니다

사용자 정보 가져오기에 실패해도 이 서버의 서명과 저장한 상대의 키는 표시됩니다.

## 결과 보는 법

항목마다 "문제 없음"・"주의"・"문제 있음"・"확인하지 않음" 중 하나와, 그 이유(HTTP 상태 코드나 연결 오류 등)가 표시됩니다. 위에서부터 차례로 보면 어디서 연합이 멈춰 있는지 알 수 있습니다.

::: tip
"서명된 사용자 정보 가져오기"는 서명을 확인하지 않고 돌려주는 서버도 많기 때문에, 상대가 이 서버를 차단하고 있어도 "문제 없음"이 될 수 있습니다. 또한 상대에게서 한동안 아무것도 오지 않는 경우에는, 상대 쪽에서 이 서버로의 배달이 멈춰 있거나 이쪽을 차단하고 있을 가능성이 있습니다.
:::

## 개발자용

API는 `admin/federation/diagnose-instance`입니다(모더레이터용. 권한은 `write:admin:federation`). 각 항목에 `keys`(서명 키의 종류)가 있으며, inbox가 배달을 받지 않을 때의 결과는 `inboxNotFound`입니다.
